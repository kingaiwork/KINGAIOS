# KINGAI OS Large Artifact Publishing

## English

Large KINGAI OS artifacts are intentionally kept out of the Git repository.

### Routing policy

```text
artifact < 2 GiB   -> GitHub Release is allowed
artifact >= 2 GiB  -> Cloudflare R2
```

The public user-facing namespace remains under `os.kingai.work`.

Recommended object layout:

```text
kingai-os-releases/
├── dev/
├── beta/
├── rc/
├── stable/
├── updates/
├── repo/
├── sbom/
└── archive/
```

Example object:

```text
stable/1.0.0/KINGAI-OS-Desktop-1.0.0-amd64.iso
stable/1.0.0/KINGAI-OS-Desktop-1.0.0-amd64.iso.sha256
```

Public URL design:

```text
https://os.kingai.work/download/1.0.0/desktop
https://os.kingai.work/updates/
https://os.kingai.work/repo/
```

The website/Worker may map those paths to private R2 objects so the storage backend can be changed later without changing product URLs.

### Required GitHub Actions secrets

```text
R2_ACCOUNT_ID
R2_BUCKET
R2_ACCESS_KEY_ID
R2_SECRET_ACCESS_KEY
```

Never put these values in source control.

### Integrity

Every official artifact should eventually publish at least:

```text
artifact
artifact.sha256
artifact.sig
artifact.spdx.json
artifact.provenance.json
```

The private signing key must not be stored in the website or ordinary R2 credentials.

## 中文

KINGAI OS 的大型镜像不进入 Git 仓库。

发布分流规则：

```text
小于 2 GiB   -> 可以使用 GitHub Release
大于等于 2 GiB -> Cloudflare R2
```

用户始终通过 `os.kingai.work` 获取文件，R2 只是后台对象存储，因此未来更换存储服务也不需要修改公开下载地址。

GitHub Actions 需要配置：

```text
R2_ACCOUNT_ID
R2_BUCKET
R2_ACCESS_KEY_ID
R2_SECRET_ACCESS_KEY
```

这些 Secret 严禁写入源码。

正式镜像应逐步同时发布 SHA256、签名、SBOM 和构建 Provenance。发布签名私钥必须与网站和普通 R2 API 密钥隔离。
