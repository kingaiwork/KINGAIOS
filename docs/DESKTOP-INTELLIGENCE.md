# KINGAI Intelligence

KINGAI Intelligence is the flagship AI-first experience inside **KINGAI OS Desktop**, the single personal-computer / PC edition of KINGAI OS.

It is not a separate operating-system profile. It shares the same Desktop Core and the same governed runtime used by KINGAI Flow and KINGAI Classic.

## Current Phase 2 shell

The current shell establishes eight first-class desktop centers:

1. Home
2. Agents
3. Tasks
4. Approvals
5. Memory
6. Models
7. Automations
8. System Health

The application lives under `desktop/intelligence/` and is installed into the Desktop root filesystem through the shared desktop asset tree.

The application launcher is `kingai-intelligence.desktop`. It also registers the local `kingai://` deep-link scheme so system surfaces can open a specific center without inventing a second privileged API.

Examples:

```text
kingai://home
kingai://agents
kingai://tasks
kingai://approvals
kingai://memory
kingai://models
kingai://automations
kingai://health
```

Unknown or malformed center values fail back to Home.

## Security boundary

Phase 2 deliberately separates **overview UI** from **privileged runtime operations**.

The Intelligence shell reads only:

```text
/run/kingai/public-status.json
```

This file is the sanitized status surface already generated by `kingaid`.

The shell must not use the public status channel to expose:

- prompt text;
- task goals;
- task targets;
- approval targets;
- secrets;
- API keys;
- passwords;
- memory content.

The repository contract in `scripts/validate-desktop.sh` rejects direct access from the public shell to private Task, Approval or Memory list endpoints.

When interactive operations are added to the centers, they must continue through the governed runtime path:

```text
Desktop UI
  ↓
Local user identity
  ↓
KINGAI Runtime API / CLI bridge
  ↓
Agent identity
  ↓
Capability Policy
  ↓
Approval when required
  ↓
Constrained execution
  ↓
Audit
```

The UI must not gain an alternate path around Policy or Approval merely because it is a KINGAI-owned application.

## Agent Center integration

The Plasma Agent Center remains a compact always-available status surface. It uses the same sanitized public status file and now deep-links into:

- KINGAI Intelligence Home;
- Approval Center;
- Task Center.

This makes the panel widget a lightweight system entry point while keeping the larger workspace in a dedicated application window.

Changing experience changes presentation and workflow, not authority.

## Validation

Desktop Phase 2 is guarded by:

```bash
make desktop-validate
```

This validates:

- Desktop remains the only PC platform profile;
- exactly three KINGAI desktop experiences exist;
- KINGAI Intelligence is the single default;
- theme and layout assets match their manifests;
- all eight Intelligence centers exist;
- the shell uses only the sanitized public status channel for overview data;
- the `kingai://` handler is registered;
- launcher deep links are constrained to known centers;
- malicious or malformed deep-link input falls back to Home.

GitHub Actions runs the same contract in `.github/workflows/desktop-contract.yml`.

## Next implementation layer

The next layer should make the centers interactive without weakening the security model:

- authenticated per-user Desktop Bridge over the existing Unix-socket identity model;
- Task list/detail and task creation;
- Approval review with scoped one-time decisions;
- Memory search with sensitivity and provenance controls;
- Model provider health and local/cloud/private/offline controls;
- Automation schedules backed by governed Task Graph execution;
- richer health diagnostics and explicitly approved repair actions.

Until those private bridges are implemented, the shell intentionally shows safe aggregate state instead of pretending unsupported private data is available.
